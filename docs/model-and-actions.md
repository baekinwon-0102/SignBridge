# 수어 모델 교체와 명령 실행

현재 모델은 assets/models/sign_language_five_words.pth의 v2 체크포인트다.
앱은 변환된 sign_language_five_words.onnx를 사용하며, 공통 설정은 assets/models/sign_model.json이다.

| 클래스 | 단어 | 실행 기능 |
| --- | --- | --- |
| 0 | 아프다 | 119 전화 앱 발신 화면 |
| 1 | 위 | 미디어 볼륨 한 단계 올리기 |
| 2 | 아래 | 미디어 볼륨 한 단계 내리기 |
| 3 | 회사 | 등록한 회사로 네이버맵 대중교통 길찾기 |
| 4 | 엄마 | 연락처 이름이 정확히 엄마인 번호로 전화 |

## 모델 입력과 변환

- 입력: float32 [1, 30, 452], 텐서명 features.
- 출력: float32 [1, 5] logits, 텐서명 logits. softmax 확률로 신뢰도를 계산한다.
- 프레임별 입력: 어깨 정규화 기본 특징 150개, 속도 150개, 가속도 150개, 오른손·왼손 감지 마스크 2개.
- 30프레임 안의 누락된 손 특징을 선형 보간하고, 앞뒤 끝은 가장 가까운 감지 프레임 값으로 채운다.
- 첫 프레임 속도와 가속도는 0이다. 감지 마스크는 원래 감지 여부를 유지한다.
- Android SignTemporalFeatures와 웹 buildTemporalFeatures를 assets/modules/features.py의 기준 결과와 비교 테스트한다.

python tools/export_sign_model.py는 체크포인트의 구조·클래스 순서를 검증하고
ONNX·라벨 맵·한국어 사전·앱 설정·검증 보고서를 생성한다.
PyTorch와 ONNX의 출력과 최상위 클래스가 일치하는지 확인한다. 변환 후 앱을 다시 빌드해야 한다.

## 인식과 실행

신뢰도 75% 이상에서 5개 단어의 기능을 자동 실행한다.
표시용 정수 확률은 버림 처리하여 74.9%가 75%로 반올림되어 실행되지 않게 한다.
새 단어는 버튼 없이 바로 실행한다. 같은 단어의 연속 프레임은 중복 실행하지 않는다.
손이 0.8초 이상 감지되지 않으면 같은 단어도 다시 실행할 수 있다.
앱 복귀 후에는 자동 실행을 계속하며, 다시 인식하기 버튼은 수동 초기화용이다.
Android와 웹은 번역 문구와 별도로 handsAbsent 신호를 전달한다. 모델 로딩·수집 문구는 손을 내린 것으로 취급하지 않는다.
개발자 모드에서는 5개 단어 버튼을 사용하고 카메라 자동 실행을 중지한다.
추론 간격은 최소 500ms이며 최초 30프레임 수집 시간이 별도로 필요하다.

회사 위치는 이름과 위도·경도를 등록한다. 엄마 전화는 연락처·전화 권한이 필요하다.
119는 전화 앱에서 통화 버튼을 눌러 발신한다.
웹은 전화 앱과 지도 연결 요청을 지원하며, 연락처 조회와 시스템 볼륨 제어는 Android에서 지원한다.
iOS 네이티브 동작은 구현되어 있지 않다.

## Android 백그라운드 인식과 PiP

단축키 실행 화면에서 `백그라운드 인식`을 켜면 카메라 유형의 foreground service가
현재 카메라와 모델을 이어받는다. 카메라 영상이 나온 상태에서 켜야 한다.
`백그라운드에서 PiP 표시`는 별도 설정이며, 끄고 `백그라운드 실행`을 누르면
작은 창 없이 인식을 계속한다. 홈 버튼으로 나갈 때도 PiP 설정을 적용한다.
PiP를 닫거나 화면이 제거되어도 서비스가 켜져 있으면 인식을 유지한다.
앱의 스위치 또는 상시 알림의 `인식 중지`로 끌 수 있다.
개발자 모드, 비서 또는 안내 화면으로 전환할 때는 백그라운드 인식을 중지한다.

PiP 상단에는 `위 · 97% | 5.4 FPS`처럼 단어, 신뢰도, 처리 FPS를 표시한다.
FPS는 약 1초 구간에 손·자세 추적과 필요한 수어 추론을 마친 프레임 수다.
카메라의 촬영 FPS나 초당 분류 횟수와는 다르다. 모델 수집 중에는 진행 상태를 표시한다.

화면이 없을 때도 75% 기준과 손을 0.8초 내리는 재실행 조건을 유지한다.
볼륨 조절은 서비스에서 바로 실행한다. 전화·길찾기는 PiP가 보이고 잠금이 없으면
기존 기능에 연결하며, 창이 없으면 실행 알림을 눌러 앱을 연 뒤 처리한다.
foreground service 자체에는 다른 앱 화면을 강제로 열 권한이 없기 때문이다.
알림이 꺼져 있으면 백그라운드 모드를 켜지 않고 앱 알림 설정으로 안내한다.
119는 기존과 같이 발신 화면까지만 연다.

서비스는 프로세스 종료 후 자동 재시작하지 않는다. 강제 종료, 권한 회수,
기기별 절전 및 카메라 경합으로 중지되면 앱에서 다시 켜야 한다.
카메라 오류는 인식을 중지하고 재시도 안내 알림으로 표시한다.

참고: [카메라 foreground service](https://developer.android.com/develop/background-work/services/fgs/service-types#camera),
[백그라운드 화면 실행 제한](https://developer.android.com/guide/components/activities/background-starts).

실기기 확인 항목:

- PiP ON/OFF 각각 홈 버튼과 백그라운드 실행 버튼으로 전환한다.
- PiP 단어·신뢰도·처리 FPS가 갱신되는지 확인한다.
- PiP를 닫고 `위/아래`로 미디어 볼륨이 한 단계씩 변경되는지 확인한다.
- 창 없는 상태의 전화·지도 알림을 누르면 해당 기능으로 연결되는지 확인한다.
- 같은 단어 유지, 0.8초 손 내리기, 앱 복귀에서 중복 실행 여부를 확인한다.
- 알림 중지, 알림 거부, 카메라 권한 회수 및 다른 앱의 카메라 점유를 확인한다.
- 화면 잠금과 프로세스 종료 뒤 실제 서비스 상태 및 재시도 안내를 확인한다.

서비스의 명령 게이트는 `test/BackgroundCommandGateCheck.java`, Flutter 설정·전환은
`test/pip_test.dart`에서 검증한다. 이 테스트들은 실기기 카메라/서비스 생명주기 검증을 대체하지 않는다.

## 검증

Flutter 테스트는 플랫폼 호출을 대체하여 75% 미만 거부, 75% 허용,
5개 기능 연결과 중복 실행 방지를 확인한다. 실제 전화를 걸지 않는다.
Java·웹 테스트는 Python의 기본 특징과 시간 특징을 비교한다.
모델 변환 검증만으로 실제 수어 인식 정확도를 확인할 수는 없다.
실기기에서는 5개 단어의 영상과 연락처 권한, 지도 실행, 볼륨 변경을 확인한다.
119는 실제 발신 없이 발신 화면까지만 확인한다.
